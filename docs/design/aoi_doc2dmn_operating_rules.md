## 1. 判断を3つに分ける

判断が要る点は、必ず次の3つのどれかに分けてから出す。**どれに入るか迷ったら、1段重い区分に入れる。**

| 区分 | 何が入るか | 扱い |
|---|---|---|
| **既定採用** | 後から簡単に戻せるもの。または、確定済みの D・P 番号を当てはめただけのもの | 推奨どおり採用して先に進む。報告の末尾に一覧（内容・根拠の D／P 番号）だけ載せ、本書 7章の「既定採用の記録」に足す。Kazuhiro さんは後から覆せる |
| **一目確認** | 戻せるが、方針に関わるもの | 「はい／いいえ」で答えられる1文にして出す。推奨の答えを添える |
| **要判断** | 戻しにくいもの。IR スキーマの型、設計原則、評価の合格条件、正解データの承認 | 2章の形にそろえて出す |

## 2. 要判断の書き方

1件ずつ、次の5項目にそろえる。

| 項目 | 書き方 |
|---|---|
| 問い | 1行 |
| 背景 | 2行まで |
| 選択肢と推奨 | 選択肢を並べ、推奨に印を付ける |
| 間違えたら何が起きるか | 推奨を採って外れた場合、別の選択肢を採って外れた場合 |
| それ待ちで止まっている作業 | 判断が出るまで進められない作業 |

## 3. 正解データのレビュー

正解ラベル・正解の Action など、正解データの承認は「要判断」に当たる。Kazuhiro さんの読む量を減らすため、差分を中心にする。

1. **正解の案を2つ、独立に作る。**
   - 案A：web Claude が作る。
   - 案B：プロンプトを変えて、別のモデルで作る。案A を見せない。
   - 当面は、web Claude が起動するサブエージェント（別のモデル）を使う。モデルの選び方は「既定採用の記録」に残す。
2. **2案が食い違った件は、精読用にする。**今までのレビュー資料と同じ形（推奨・根拠・判断欄）で出す。
3. **2案が一致した件は、条文とラベルを並べた一覧にする。**
4. **一致した件からも、毎回2〜3件を無作為に選んで精読用に加える。**選び方（乱数の種）は資料に書く。
   - そこで誤りが見つかったら、次回からは全件を精読用に戻す。
5. 案A・案B と、食い違いの件数は、評価の記録として残す（2案の一致率は、正解の作りやすさの目安になる）。

## 4. 止まる条件

次のどれかに当たったら、作業を止めて Kazuhiro さんに報告し、続行の確認を取る。

| # | 止まる条件 |
|---|---|
| S1 | 正解データや評価セットの承認が必要になった |
| S2 | 保留評価など、1回しか流せない評価を実行する直前 |
| S3 | 同じ評価で2回続けて不合格だった |
| S4 | 確定済みの判断（D・P 番号）を覆す提案が出た |
| S5 | 上のどれにも当たらなくても、前に止まってから HANDOFF を2回出した時点（2〜3回ごとの下限をとる） |

Claude Code 向けの HANDOFF には、次の2つを必ず書く。
- 「1回の HANDOFF の中で、同じ作業の再試行は **2回まで**。超えたら報告して止まる」
- その HANDOFF の中で当たりうる止まる条件（S1〜S4）と、止まったときに報告すること

## 5. 報告の形

報告は止まる地点でまとめて出す。web Claude から Kazuhiro さんへの報告も、Claude Code から web Claude への報告（HANDOFF_*_to_web.md）も、冒頭は次の3行にする。

```
分かったこと：（1行）
次にすること：（1行）
判断が要る点：要判断 N件／一目確認 N件（既定採用 N件は末尾に記録）
```

本文は、要判断 → 一目確認 → 中身の説明 → 既定採用の一覧、の順に並べる。
